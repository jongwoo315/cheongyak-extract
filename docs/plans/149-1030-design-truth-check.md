# #149 설계 — 청약홈 정답과 공고문 PDF 값 20건 대조

## jw 기준

공고 20건을 열어서 html값과 pdf값을 비교하고 90%이상 일치한다

## 착수 때 확인한 사실 (2026-10-30, main `f8986eb`)

1. 지금까지 정답은 청약홈 상세 HTML(`data/raw/<pbno>/detail.html`)을 `truth.parse_truth`로 읽은 값이다. #147 LLM(맞은 칸 96.25%)과 #150 정규식(69.4%)이 모두 이 정답으로 쟀다
2. #147·#150이 잰 공고 20건(`reports/extract-new.md` 맨 위 목록)은 8필드 모두 HTML 정답이 차 있다. 160칸 전부 정답이 있다
3. #147 LLM이 「정답과 다른 값으로 채운」 6칸 중 일부는 PDF 쪽이 HTML과 다르게 적혀 있다
   - 2026000454 입주예정월: HTML `2026.10`, PDF 근거 문장 「본 아파트는 2025년 10월 27일 동별준공으로」
   - 2026000314 시공사: HTML은 한 회사, PDF 상호 줄은 두 회사
   - 2026000437 공급위치: HTML `고덕동 고덕면`, PDF `고덕동, 고덕면`(쉼표 하나 차이)
4. 20건 HTML에는 「정정」이라는 글자가 없다. PDF 20건에는 「정정」이 3~9번씩 있다. 공고마다 반복되는 안내 문구인지 실제 정정인지는 아직 보지 않았다
5. 정규화는 `normalize.normalize(field, value)`, 근거 확인은 `extract.grounded(evidence, page_text)`(공백을 모두 지우고 포함 여부)다. 쪽 텍스트는 `pdf_text.pages(path)`(sort=True)이고 리스트 인덱스 + 1이 쪽 번호다
6. #146 리뷰 #9(사이트가 비워 둔 칸과 파서가 못 찾은 칸 구별)는 이 20건에 해당 칸이 없다(사실 2)

## 설계 결정

### 대조할 공고와 칸

- #147·#150이 잰 공고 20건, 필드 8개, 160칸이다. 같은 공고를 써야 결과로 LLM·정규식 점수를 다시 읽을 수 있다
- 칸 하나 = 공고 하나 × 필드 하나

### PDF 값은 누가 어떻게 적나

- 구현 루프가 PDF를 읽고 칸마다 값을 적는다. jw가 손으로 적는 것이 아니다 — Kickoff에서 jw가 바꿀 수 있다
- 필드의 뜻은 LLM 프롬프트의 필드 정의(`extract._FIELD_HELP`)와 같다. 예: 공급규모는 「이번에 분양하는 세대수 하나」
- 칸마다 `value`, `quote`(값이 적힌 줄을 PDF 텍스트에서 글자 그대로), `page`, `note`를 적는다
  - PDF가 값을 정정했으면 정정 뒤 값을 쓰고 `note`에 정정 전 값과 근거를 적는다
  - PDF에 그 값이 없으면 `value`·`quote`·`page`를 null로 두고 `note`에 찾아본 곳을 적는다
- 코드가 `quote`가 그 쪽 텍스트에 있는지 `grounded`로 검사한다. 없는 칸이 하나라도 있으면 측정을 다시 한다
- PDF 값을 적는 동안 `detail.html`과 기존 리포트(`reports/extract-*.md`, `reports/regex-*.md`)를 열지 않는다. HTML 값을 보고 PDF 값을 맞추지 않으려는 것이다. PDF 값 파일 커밋이 비교 실행보다 앞이어야 한다(커밋 순서로 확인)

### 같다고 보는 기준

- 본 수치: `normalize(field, html) == normalize(field, pdf)`인 칸 수 / 160. #147·#150 채점과 같은 기준이다
- 같지 않은 칸은 원인을 넷 중 하나로 적는다
  - 표기 차이: 뜻은 같은데 정규화가 못 맞췄다(쉼표·괄호·주식회사 위치 등)
  - 정정: PDF가 값을 고쳤다고 적었다
  - 다른 값: HTML과 PDF가 다른 값을 적었다
  - PDF에 없음
- 참고 수치: 「표기 차이」를 같은 칸으로 쳤을 때의 비율. 본 수치를 대신하지 않는다

### LLM·정규식 점수를 다시 읽는 표

- #147 LLM이 정답과 다른 값으로 채운 6칸, #150 정규식이 정답과 다른 값으로 채운 15칸마다 추출값이 PDF 값과 정규화 뒤 같은지 적는다
- LLM 칸은 `compare.parse_llm_new`로 커밋된 `reports/extract-new.md`에서 읽는다. 정규식 칸은 `compare.regex_cells`로 다시 뽑는다. OpenAI를 부르지 않는다
- 이 표는 읽는 법만 보탠다. eval의 정답을 PDF 값으로 바꾸지 않는다

## 이번에 안 하는 것

- eval 정답을 HTML에서 PDF 값으로 바꾸는 것, LLM·정규식 점수를 다시 매겨 기존 리포트를 고치는 것
- 정규화 규칙 수정(표기 차이 칸이 나와도 고치지 않는다)
- 20건 밖의 공고, PDF에만 있는 필드(#152), 결정 기록(#153)
- LLM을 부르는 것
