# #153 설계 — HTML과 PDF 중 어느 쪽 청약정보가 맞는지 jw가 가릴 수 있게 한다

**Notion:** #153 결정 기록: 어떤 방식을 왜 골랐나

## jw 기준

html로 측정한 청약정보와 pdf로 측정한 청약정보를 비교하고 두 방식의 우위를 가릴 수 있다

- 되물음(우위는 무엇으로 가리나)에 대한 jw 답: 「어느 쪽도 정답이라 확실할 수 없다면 어느 쪽이 맞는지는 내가 보고 판단하는 영역이 된다」

## 착수 때 확인한 사실 (main `61586bf`)

1. 청약홈 상세 HTML(`truth.parse_truth`)에서 읽는 필드는 8개다. 전매제한 기간·거주지 우선 비율·신혼부부 소득 기준 3개는 HTML에 없고 공고문 PDF에만 있다(#152)
2. 공고 20건 × 8필드 = 160칸에 세 값이 이미 있다
   - HTML 값: `detail.html`
   - PDF 값: 구현 루프가 PDF를 읽고 적은 `labels/pdf-values-20.json`(#149, 칸마다 `quote`·`page`)
   - LLM 값: #147이 같은 20건에서 PDF로 뽑은 값. HTML과 다른 칸만 `reports/extract-new.md` 「틀리게 채운 칸」 표에 있다. 나머지는 HTML과 정규화 뒤 같다
3. `reports/truth-check.md`(#149): HTML과 PDF 값이 다른 칸 5(표기 차이 3, 다른 값 2). LLM이 HTML과 다른 칸 6 중 4칸은 PDF 값과 같다
4. 두 묶음을 합치면 세 값이 모두 같지 않은 칸은 7칸이다(2026000443·2026000437·2026000438 공급위치, 2026000454 입주예정월, 2026000314 시공사, 2026000437·2026000438 시행사)
5. `truth_check.run_check`가 이미 HTML·PDF 값·LLM 값을 한 번에 읽는다. OpenAI와 청약홈을 부르지 않는다

## 설계 결정

### 무엇과 무엇을 비교하나

- HTML 방식: 청약홈 상세 HTML 표에서 읽은 값
- PDF 방식: 공고문 PDF에서 읽은 값. 시스템이 실제로 쓰는 방식인 LLM 추출 값을 본 값으로 두고, 구현 루프가 PDF를 읽고 적은 #149 값(근거 줄·쪽)을 같이 보여 준다
- 칸 하나 = 공고 하나 × 필드 하나. 범위는 #147·#149의 공고 20건, 8필드, 160칸이다. 새로 LLM을 부르지 않는다

### 누가 어느 쪽이 맞는지 정하나

- HTML 값·PDF 값·LLM 값이 정규화 뒤 모두 같은 칸은 「같은 칸」으로 센다. 이 칸은 두 방식 모두 맞다고 본다는 가정을 리포트 맨 위에 적는다
- 하나라도 다른 칸은 판정 파일 `labels/source-judge.json`에 넣는다. 칸마다 HTML 값, PDF 값과 근거 줄·쪽, LLM 값, 빈 `jw` 칸을 둔다
- `jw` 칸은 jw가 PR 게이트에서 채운다. 값은 넷 중 하나다: `HTML`(HTML 쪽이 맞다) / `PDF`(PDF 쪽이 맞다) / `둘 다`(같은 뜻이다) / `둘 다 아님`. 채운 뒤 `jw-note`에 한 줄을 적을 수 있다
- 구현 루프는 `jw` 칸을 채우지 않는다. 어느 쪽이 맞는지 짐작해 적는 칸도 두지 않는다

### 집계

- `judge-source` 명령: 판정 파일이 없으면 만들고, 있으면 그대로 읽어 `reports/source-judge.md`를 쓴다
- 리포트 내용
  - 같은 칸 수 / 160, 판정할 칸 수 / 160
  - 판정할 칸 표: 공고·필드·HTML 값·PDF 값·근거 쪽·LLM 값·jw 판정
  - jw 판정을 센 표: `HTML`·`PDF`·`둘 다`·`둘 다 아님`·`판정 전` 칸 수. `판정 전`이 하나라도 있으면 맨 위에 「jw 판정 전」이라고 적고 방식별 합계를 쓰지 않는다
  - 방식별로 맞는 값을 가진 칸 수: 같은 칸 + jw 판정이 그 방식이거나 `둘 다`인 칸. 판정 전이면 쓰지 않는다
  - HTML에 없는 필드: 3개 필드는 HTML 쪽 값이 0칸이다. PDF 쪽은 #152 리포트 숫자를 출처와 함께 옮긴다
- 근거 줄 검사: 판정할 칸의 PDF 근거 줄이 그 쪽 텍스트에 있는지 `extract.grounded`로 본다. 없는 칸은 리포트에 적고 종료 코드 1
