## 설계 결정

### 「수집됐다」와 「오류」의 뜻

- **수집된 공고**: `data/raw/<pbno>/`에 `detail.html`이 있고 `notice.pdf`가 pymupdf로 열린다(쪽 수 1 이상, 마지막 쪽 텍스트를 읽을 수 있다)
- **150건**: `data/raw/` 전체에서 수집된 공고 수다. 이미 받은 49건을 포함한다. 이번에 새로 받는 수는 150 − (실행 직전 수집된 공고 수)다
- **오류**: 아래 셋
  - 요청이 실패해 공고를 못 받았다(HTTP 상태 오류, 타임아웃, 연결 끊김). 다시 시도한 뒤에도 실패한 것만 센다
  - `data/raw/`에 열리지 않는 `notice.pdf`가 있다
  - `fetch`가 n건을 못 채우고 멈췄다(목록 끝, 403·429 연속, 목록 요청 실패)
- **오류가 아닌 것**: 상세에 공고문 링크가 없는 공고(LH 등), 첨부가 정말 PDF가 아닌 공고(본문이 `%PDF-`로 시작하지 않는다). 수집 대상이 아니므로 건너뛰고 공고 번호와 이유를 따로 센다
  - jw 기준이 「오류」를 정의하지 않았다. 이 구분은 Claude가 정했다. PR 게이트에서 jw가 다르게 볼 수 있으므로 PR 본문에 건너뛴 공고를 이유별로 전부 적는다

### 잘린 PDF를 남기지 않는다

- PDF를 `notice.pdf.part`에 쓰고, 열리는지 확인한 뒤 `notice.pdf`로 이름을 바꾼다. 열리지 않으면 `.part`를 지우고 오류로 센다
- 이미 있는 `notice.pdf`도 열리는지 본다. 열리면 요청 없이 건너뛰고, 안 열리면 다시 받는다

### PDF 판정에 본문을 같이 본다

- 파일 이름이 `.pdf`로 끝나거나, 본문이 `%PDF-`로 시작하면 PDF다
- 둘 다 아니면 「첨부가 PDF가 아님」. 첨부가 여럿이면 지금처럼 다음 첨부를 본다

### 일시 오류는 두 번까지 다시 시도한다

- 대상: 5xx, 타임아웃, 연결 끊김. 목록·상세·PDF 요청 모두
- 쉬는 시간: 첫 재시도 전 5초, 두 번째 전 15초. 요청 사이 2초는 그대로다
- 403·429는 다시 시도하지 않는다. 지금처럼 3번 연속이면 멈춘다 — 막힌 상태에서 요청을 늘리지 않는다
- 다시 시도한 횟수를 `FetchResult`에 세고 `fetch` 출력에 찍는다

### 확인 명령 `check-raw`

- `data/raw/`를 읽기만 한다. 청약홈에 요청하지 않는다
- `reports/raw.md`에 쓴다: 공고 디렉터리 수, 수집된 공고 수, 열리지 않는 PDF(공고 번호·이유), PDF가 없는 공고(공고 번호·상세에 링크가 있는지)
- jw 기준을 이 리포트로 잰다
